# census10to20 Conversion Bug — Data Impact & Regeneration Plan

**Status:** fix released as `sdc-census10to20 v0.1.2` (2026-06-03). Affected
distribution data NOT yet regenerated.

## The bug

`convert_2010_to_2020_bounds` (and `standardize_all`, which calls it) redistributes
pre-2020 sub-county census data onto 2020 boundaries. Before v0.1.2 it weighted
"moved" overlaps by `area_part/area20` and passed "same"/"split" through unchanged,
so a 2010 tract that **split** replicated its full value to each 2020 child —
**inflating counts**. The fix weights by the source-area share `area_part/area10`,
which conserves totals. See `docs/specs/2026-06-03-census10to20-count-conservation-fix-design.md`
and `reference_census10to20_convert_semantics` (memory).

## Scope of corruption (what is wrong)

Only the **redistributed `_geo20` measures** for:
- **sub-county rows** (tract `geoid` len 11, block group len 12),
- **years < 2020**,
- where the 2010 source tract **split or moved** (unchanged "same" tracts are correct).

Correct/unaffected: original `_geo10` values; all `year >= 2020` rows; rows in
counties whose tracts didn't change; non-sub-county geographies. Errors are
**over-counts** (too large). Because the bug inflated, county/HD aggregates built
from the bad `_geo20` rows are also too high.

## Verification (real distribution data)

`demographics/Age`, NCR, 2018, tract level, `age_total_count`. County `_geo20`
totals should equal `_geo10` totals (county boundaries are fixed):

- NCR-wide: **15,101,707 (`_geo10`) → 17,992,074 (`_geo20`) = +19.1%**.
- Per-county ratio `geo20/geo10` ranges 1.00 (no tract change, correct) to **2.00**
  (a tract split in two → both children received the full value). Many counties
  1.2–1.8×.

Reproduce / acceptance test after regeneration (ratios should all be ≈1.00):

```python
import pandas as pd
df = pd.read_csv(PATH, dtype={"geoid": str})
tr = df[(df.year < 2020) & (df.region_type == "tract")].copy()
tr["county"] = tr["geoid"].str[:5]
for base in sorted({m[:-6] for m in tr.measure.unique() if m.endswith("_geo20")}):
    g10 = tr[tr.measure==base+"_geo10"].groupby("county").value.sum()
    g20 = tr[tr.measure==base+"_geo20"].groupby("county").value.sum()
    r = (g20/g10).dropna()
    print(base, "max county ratio:", round(r.max(), 3))  # ~1.0 == fixed
```

## Regeneration plan

Each affected dataset is regenerated by re-running its `code/distribution/ingest.py`
(and `prepare.py` where standardization happens) against the fixed code (the uv
workspace now resolves the corrected `sdc-census10to20`; confirm with
`uv run python -c "import sdc_census10to20; print(sdc_census10to20.__version__)"`).
Then re-run the dataset's `prepare.py` to refresh dashboard outputs, and run the
acceptance test above.

### Order (inputs before composites)

**Phase 1 — base ACS indicators** (independent; each fetches from the Census API,
so `CENSUS_API_KEY` must be set):
`demographics/{Age, Race, Gender, Language, Veteran, Population Density,
Cooperative extension}`, `financial_well_being/{Household Income, Income Inequality,
Employment Rates}`, `health/System Usage and Insurance/Without Health Insurance`,
`education/{Years of Schooling, Postsecondary}`, `broadband/Household Broadband`,
`transportation/Population Characteristics`, `financial_well_being/Material_Deprivation`.

**Phase 2 — composites / HOI / derived** (depend on other indicators or external
services; regenerate after their inputs, per each `pipeline.yaml`):
`environment/Environmental Hazard Index (HOI)` (EPA inputs),
`food/Food Access/Food Accessibility Indicator (HOI)`,
`public_safety/Incarceration (HOI)`,
`demographics/{Geographic Mobility (HOI), Segregation Index (HOI)}`,
`financial_well_being/Employment Access Index`,
`transportation/Walkability` (OSM/transit inputs),
`housing/Cost/Affordability_HT` (housing + transport inputs).

### Prerequisites & cautions
- **Census API key** for all Phase 1 ACS pipelines.
- **External services** for some Phase 2: EPA (Environmental Hazard), OSM/transit
  (Walkability) — confirm access before batching.
- Re-running fetches **current** source data; ACS vintages are stable, but expect
  trivial diffs unrelated to the fix. The acceptance test isolates the fix
  (geo20/geo10 county ratios → ~1.0).
- After regenerating distribution files, re-run each dataset's `prepare.py` so the
  `dashboard_data/` outputs (county/health-district aggregates) pick up the
  corrected values, and re-run validation comparisons.
- Commit regenerated `data/distribution/*.csv.xz` per dataset (or per phase).

### Acceptance per dataset
The geo20/geo10 county-ratio test (above) returns **max ratio ≈ 1.0** for every
pre-2020 `_geo20` count measure.
